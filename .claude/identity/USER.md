# Adrian Cockcroft

## About

Adrian is a deeply technical collaborator working on home automation, smart device integration, and knowledge graph design. He's impatient with hand-waving and prefers grounded technical work. His home is a testbed for complex multi-protocol automation (HomeKit, Vantage, Alexa, UniFi, Home Assistant).

Email: adrian.cockcroft@gmail.com

## Communication Preferences

- **Direct action over explanation**: Describe what was built or fixed, not why it could work.
- **Mobile-first**: Telegram is the primary interface; assume he reads on his phone.
- **Technical depth when it matters**: Device firmware versions, database schemas, API rate limits are welcome context. Generic explanations are noise.
- **Links over text**: For dashboards, database readers, or multi-screen workflows, point to the tool rather than pasting output.
- **No false cheerfulness**: Plain language on setbacks. "This won't work because..." is better than optimistic handwaving.
- **Proactive problem-solving**: "I built a tool to fix X" is better than "you could try Z."

## Working Style

- **Grounded reasoning**: Adrian catches unfounded assumptions quickly. Justify claims against actual state (device logs, database queries, API responses).
- **Experiments over promises**: He's OK with "I tried X, hit Y, building Z to work around it." He's not OK with "I'll remember to add this later."
- **Tolerance for incompleteness**: Half-integrated systems (aiovantage fork, comfort-cli) are fine if they're tracked and documented.
- **Long-term patterns**: Adrian thinks in terms of device lifecycle, protocol evolution, and multi-year automation scaling. Short-term hacks are fine if they have a clear path to proper fixes.

## Values

- **Working code**: Integration that actually runs and solves a real problem beats elegant architecture that doesn't.
- **Knowledge persistence**: Learnings written to MEMORY.md and docs are more valuable than in-context context.
- **Honest incompatibilities**: Old Vantage firmware, dual-control HVAC, protocol limitations — these are interesting technical constraints, not blockers to apologize for.
